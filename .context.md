# OpenERP - Contexto do Projeto

## Estrutura do Projeto
- Backend: Go 1.21+
- Banco de Dados: MySQL 8.0 (etools_openerp)
- ORM: GORM
- Injeção de Dependência: Wire
- Framework Web: Gin
- Autenticação: JWT

## Models já criados
- Usuario, GrupoUsuario, UsuarioFilial
- Empresa, EmpresaFilial, Entidade
- Produto, ProdutoGrupo, ProdutoSubgrupo, ProdutoMarca, ProdutoEspecie, ProdutoModelo, ProdutoSerie, TipoProduto
- ProdutoVariacao, ProdutoCor, ProdutoTamanho
- TabelaPreco, TabelaPrecoProduto, TabelaDesconto
- DocumentoVenda, DocumentoVendaItem, DocumentoVendaPagamento
- FormaPagamento, CondicaoPagamento
- Portador, ConvenioBancario, ContaBancaria, Banco
- RotinaContabil, PlanoContasFinanceiro
- Pais, Estado, Municipio, Moeda, MoedaCotacao
- Horario, HorarioPonto, HorarioTurno, Setor, CentroDeCusto
- OperacaoFiscal, CSTICMS, CSTIPI, CSTPISCOFINS
- EntidadeEndereco, EntidadeContato, FormaContato, EntidadeDocumento, EntidadeRegimeTributario
- ConfiguracaoDelivery, PedidoWhatsApp

## Architecture
- Repository Pattern: repository/
- Service Layer: service/
- Dependency Injection: wire/
- Handlers: handler/
- DTOs: dto/
- Utils: utils/
- Constants: constants/

## Autenticação JWT
- Login: POST /api/v1/auth/login
- Refresh: POST /api/v1/auth/refresh
- Me: GET /api/v1/auth/me
- Logout: POST /api/v1/auth/logout

## Status Atual
- **Autenticação**: 100% funcional (Login, Refresh, Me, Logout).
- **Módulo de Entidades**: 100% funcional (CRUD de Entidade, Endereços, Contatos, Grupos, Regimes Tributários, Limites de Crédito).
- **Módulo de Produtos**:
    - CRUD de Produto, Grupos, Subgrupos, Marcas, Modelos, Tabela de Preços: 100% funcional.
    - Variações de Produto (Cores/Tamanhos): O serviço `ProdutoVariacaoService` e seus serviços dependentes (`ProdutoCorService`, `ProdutoTamanhoService`) estão implementados, permitindo a gestão de variações. A integração completa com o conceito de "grade" pode necessitar de refinamentos adicionais.
    - Estoque Inicial: Não iniciado.
- **Módulo de Pedidos (Documentos de Venda)**:
    - CRUD de Documentos de Venda e Itens: A estrutura principal está implementada, mas o fluxo de alteração de status e regras de negócio associadas ainda não estão completos.
    - Pagamentos do Pedido: O modelo existe, mas a lógica de negócio para gestão de pagamentos não está totalmente implementada no serviço.
    - Fluxo de Situações (Aberto → Em atividade → Fechado): Não iniciado.
    - Tipos de Entrega, Taxa de Entrega, Descontos e Acréscimos: Campos e DTOs para estas funcionalidades estão presentes.
    - Histórico de Pedidos: Não iniciado.
- **Módulo de Estoque**:
    - Saldo de Estoque: O campo existe no DTO de Produto, mas a lógica de cálculo e atualização não está implementada.
    - Movimentação, Baixa, Entrada, Ajustes, Histórico, Relatório: Não iniciados.
- **Módulo Financeiro**:
    - Títulos a Receber: A base para geração de títulos a partir de pagamentos de venda existe, mas o CRUD e a gestão completa dos títulos (baixa, etc.) não estão implementados.
    - Centro de Custo: O modelo `centro_de_custo.go` foi criado.
    - Títulos a Pagar, Baixas de Títulos, Remessa/Retorno Bancário, Controle de Cheques, Fluxo de Caixa: Não iniciados.
- **Módulo de Relatórios**: Não iniciado.
- **Módulo de Integrações**: Não iniciado.
- **Testes e Deploy**:
    - Testes Unitários: A estrutura de testes com `testify` está em uso, mas a cobertura precisa ser expandida.
    - Documentação API (Swagger): O `swagger.json` está bem completo e atualizado.
    - Testes de Integração, Testes de Carga, CI/CD, Deploy em Produção: Não iniciados.

## Padrões de Código
- Constantes centralizadas em constants/constants.go
- Campos de auditoria: CreatedAt, UpdatedAt, DeletedAt, CreatedBy, UpdatedBy
- Soft delete: método SoftDelete()
- Hooks GORM: BeforeCreate, BeforeUpdate (com *gorm.DB)
- Relacionamentos: usar foreignKey e references

## Melhorias e Próximos Passos
- **Refatorar Scripts PowerShell**: Unificar `dev.ps1`, `dev1.ps1` e `criar.ps1` em um único script `dev.ps1` mais robusto, utilizando o `param` block para argumentos, que é uma prática mais moderna e segura.
- **Padronizar Auditoria**: Garantir que todos os models tenham os campos `created_by` e `updated_by` e que os hooks `BeforeCreate`/`BeforeUpdate` sejam usados para preenchê-los, possivelmente extraindo o ID do usuário do contexto da requisição.
- **Melhorar Tratamento de Erros**: Padronizar as respostas de erro da API, talvez usando um `error handler` centralizado no Gin para converter erros de serviço (ex: `apperrors.NewValidationError`) em respostas HTTP 400 ou 404 apropriadas.
- **Implementar Cache**: Para dados que não mudam com frequência (ex: Tipos de Documento, Formas de Pagamento), implementar um cache com Redis (a dependência `go-redis` já está no projeto) para melhorar a performance.
- **Completar Módulo de Produtos**: Finalizar a implementação da "Grade de Produtos" com todos os atributos e lógica de estoque inicial.
- **Completar Módulo de Pedidos**: Implementar o fluxo completo de situações e o histórico de pedidos.
- **Completar Módulo de Estoque**: Desenvolver as funcionalidades de movimentação, baixa, entrada, ajustes e relatórios de estoque.
- **Completar Módulo Financeiro**: Implementar a gestão completa de títulos a pagar e a receber, fluxo de caixa e outras funcionalidades financeiras.
- **Expandir Cobertura de Testes**: Aumentar a cobertura de testes unitários e implementar testes de integração e carga.
- **Configurar CI/CD e Deploy**: Estabelecer pipelines de CI/CD para automação de testes e deploy.
